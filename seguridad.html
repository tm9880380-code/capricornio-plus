Seguridad y reporte responsable

Capricornio Plus documenta sus controles y límites técnicos para que las personas usuarias y administradoras comprendan qué protecciones existen y cómo informar vulnerabilidades de manera responsable.

Versión: 22 de noviembre de 2026Idioma: EspañolAplicación: Capricornio Plus autoalojable
Canal pendiente de asignación: el operador debe publicar un correo de seguridad monitorizado antes de anunciar un programa de reporte. No se ofrece actualmente un programa de recompensas ni un SLA público de respuesta.

1. Controles técnicos documentados

  • Hash de contraseñas mediante una función diseñada para contraseñas.
  • Tokens de sesión aleatorios; la base conserva su hash.
  • Cookie de sesión HttpOnly y SameSite=Lax; Secure se activa al configurar HTTPS.
  • Consultas SQL parametrizadas y claves foráneas.
  • Límites de intentos de autenticación y registro.
  • Cabeceras CSP, X-Content-Type-Options, X-Frame-Options, Referrer-Policy y Permissions-Policy.
  • Eliminación de cuenta con verificación de contraseña y borrado en cascada en la base activa.

2. Límites conocidos

La CSP y los controles de sesión deben verificarse en el dominio de producción. El Web Worker de Pyodide no constituye una caja de arena segura para código hostil. La plataforma necesita revisión independiente, análisis de dependencias, pruebas de penetración, monitoreo y gestión de copias antes de un despliegue público de alto riesgo.

3. Cómo reportar una vulnerabilidad

Enviar un informe a [CORREO DE SEGURIDAD] con el asunto “Reporte responsable Capricornio”. Incluir una descripción técnica, impacto potencial, versión afectada y pasos mínimos para reproducirlo. No incluir datos personales de terceros ni ejecutar pruebas destructivas. No publicar detalles explotables antes de coordinar una corrección razonable.

4. Alcance de autorización

La publicación de esta política no concede autorización para probar infraestructura, cuentas, dominios o servicios de terceros. Cualquier prueba debe limitarse a activos controlados por el operador y contar con permiso expreso.

5. Responsabilidades del operador

El operador debe mantener dependencias actualizadas, proteger secretos, restringir acceso a la base de datos, configurar HTTPS, verificar respaldos, definir respuesta a incidentes y publicar el contacto real de seguridad.
